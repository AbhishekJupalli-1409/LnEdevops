# Flux GitOps

**Tree:** `gitops/clusters/aks-centralindia/`  
**Pipeline:** `flux-bootstrap-azure-pipelines.yml`

## Introduction

**Flux** is a GitOps operator: controllers in the cluster pull from git and reconcile Kubernetes objects to match. After bootstrap you get `flux-system` components plus sync objects pointing at a path in the repo.

The hand-authored file `apps-kustomization.yaml` is a Flux **Kustomization** CR that points at `./apps` and substitutes variables from ConfigMap `cluster-vars`.

## Why we use it

Imperative `kubectl apply` from laptops drifts and is hard to audit. Git PRs become the change record. Flux continuously heals drift (someone manually deleted a Deployment → Flux recreates it).

Values like ACR login server and ACI private IP are unknown until Terraform finishes — hence `cluster-vars` substitution instead of hardcoding in git.

## Real-life example

A **living policy binder** plus a clerk who never stops comparing shelves to the binder. Sticky notes (`cluster-vars`) hold today’s warehouse address and back-office extension numbers so the binder templates stay generic.

## Connections

```
GitHub: gitops/clusters/aks-centralindia
  <-- Flux GitRepository pull
Flux Kustomization "apps"
  <-- substituteFrom ConfigMap cluster-vars
  --> applies apps/ (namespace, frontend, todolist, ingress)

cluster-vars written by bootstrap pipeline from Terraform outputs:
  ACR_LOGIN_SERVER, BACKEND_PRIVATE_IP, BACKEND_PORT

Day-2: commit YAML change --> Flux reconcile (~minutes) --> cluster updates
```

## In this project

Source of truth for AKS apps; `flux-system/` is generated by bootstrap and not hand-edited in the starter tree.
