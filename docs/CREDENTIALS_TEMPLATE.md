# Credentials document - template

This is what `scripts/generate-credentials-doc.sh` fills in and writes to
`docs/CREDENTIALS.md` after a real `terraform apply`. It's included here so
you can see exactly what will be captured and where each value actually
lives (mostly Key Vault, not this file) - I don't have your Azure
subscription, so I can't produce the real version myself.

| Item | Where it actually lives | Notes |
|---|---|---|
| Resource group name | Terraform output `resource_group_name` | not secret |
| ACR login server | Terraform output `acr_login_server` | not secret; no admin credential exists (RBAC-only) |
| AKS cluster name / kubeconfig | Terraform output `aks_cluster_name` / `kube_config_raw` (sensitive) | private cluster - only reachable from inside the VNet |
| PostgreSQL admin login | Terraform output `postgres_server_fqdn` + module output `administrator_login` | default `pgadmin` |
| PostgreSQL admin password | **Key Vault secret** `postgres-admin-password` | generated by `random_password`, never in plan/apply logs |
| PostgreSQL connection string | **Key Vault secret** `postgres-connection-string` | |
| Key Vault name | Terraform output `key_vault_name` | |
| Backend (ACI) private IP | Terraform output `aci_backend_private_ip` | not reachable from outside the VNet by design |
| Agent VM SSH private key | **Key Vault secret** `agent-vm-ssh-private-key` | break-glass only; day-to-day access is via `az vm run-command`, not SSH |
| Azure DevOps PAT(s) | Wherever you generated them (not stored by Terraform) | rotate after setup; only used to bootstrap the agent + (optionally) the AzDO project |

Nothing above is generated by me in this conversation - it's generated by
**your** `terraform apply`, because that's the only place these secrets
(random passwords, real IPs, real FQDNs) come from.
